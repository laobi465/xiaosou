### 1.2 技术选型一览

| 层级 | 选型 | 理由 |
|---|---|---|
| Web 服务器 | Nginx 1.22+ | 高并发、配置灵活、PHP-FPM 集成成熟 |
| PHP | PHP 8.2+ | ThinkPHP8 最低要求，性能与类型系统优秀 |
| 框架 | ThinkPHP 8.0 | 多应用、ORM、队列、命令行开箱即用，契合原生 PHP 模板渲染 |
| 模板引擎 | ThinkPHP View (PHP 原生标签) | 契合"原生 PHP"定位，无前端构建负担 |
| 数据库 | MySQL 8.0 | FULLTEXT 中文索引（ngram 解析器）、CTE、窗口函数 |
| 缓存 | Redis 7.0 | 验证码/限流/会话/队列/分布式锁统一 |
| 邮件 | PHPMailer 6.x | SMTP 协议成熟库，支持授权码 |
| 支付 | 彩虹易支付（自封装 SDK） | 标准 form + MD5 签名，无需第三方包 |
| 队列 | think-queue 5.x（Redis 驱动） | 与 TP8 原生集成 |
| 前端交互 | 原生 JS + Alpine.js（可选轻量） | 少量交互场景，避免重型框架 |
| CSS | Pico.css / Bootstrap 5（按需） | 轻量响应式，快速落地 |
| 图标 | Tabler Icons | SVG 矢量，按需引入 |

### 3.2 积分模块 (CreditService)

```php
class CreditService {
    /**
     * 扣减积分(防超扣)
     * 使用事务 + 乐观锁(version 字段)
     */
    public function consume(int $userId, int $amount, int $type, int $relatedId = null, string $remark = ''): bool {
        return Db::transaction(function() use ($userId, $amount, $type, $relatedId, $remark) {
            $credit = UserCredit::where('user_id', $userId)->lock(true)->find();
            if (!$credit || $credit->balance < $amount) {
                throw new CreditNotEnoughException();
            }
            // 乐观锁更新
            $affected = UserCredit::where([
                ['user_id', $userId],
                ['version', $credit->version],
            ])->update([
                'balance' => $credit->balance - $amount,
                'total_consume' => $credit->total_consume + $amount,
                'version' => $credit->version + 1,
            ]);
            if (!$affected) throw new \Exception('并发冲突,请重试');
            // 写流水
            CreditLog::create([...]);
            return true;
        });
    }
    
    public function recharge(int $userId, int $amount, int $type, int $relatedId, string $remark): void { /* 类似 */ }
}
```

**关键设计**：
- `SELECT ... FOR UPDATE` 行锁 + `version` 乐观锁双重保险
- 流水表记录 `balance_after`，便于追溯
- 流水类型枚举：1充值 2消耗 3签到 4注册赠送 5提交奖励 6管理员调整

```php
        // 投递到 crawl 队列
    }
    
    public function execute(CrawlTask $task): void {
        // 1. 通过 pan_sources.crawler_class 反射实例化采集器
        // 2. 调用 crawl() 获取结果
        // 3. 敏感词过滤
        // 4. URL hash 去重(resource_links.url_hash UNIQUE)
        // 5. 入库 resource_links + 关联 resources
        // 6. 写 crawl_logs
        // 7. 失败重试 3 次
    }
}
```

**调度策略**：
- `think crawl:dispatch` 每分钟扫描 `crawl_tasks` 表，`next_run_at <= now` 的任务入队，并更新 `next_run_at = now + frequency`
- 队列消费 `think crawl:consume` 多进程并行（按网盘源隔离队列通道）
- 单源采集失败不影响其他源

## 四、接口与路由设计规范

### 4.1 路由规范

| 类型 | 风格 | 示例 |
|---|---|---|
| 前台页面 | RESTful 风格路由组 | `/search`、`/resource/{id}`、`/user/credits` |
| 异步接口 | `/ajax/xxx` 前缀 | `/ajax/search/hot`、`/ajax/ad/click` |
| 后台页面 | `/admin/xxx` | `/admin/resource/index` |
| 支付回调 | 不带前缀 | `/pay/notify`、`/pay/return` |

### 4.2 统一响应格式（Ajax 接口）

```json
{
  "code": 0,           // 0=成功 非0=错误码
  "message": "success",
  "data": { },
  "request_id": "xxx"  // 链路追踪
}
```

错误码定义：
- `0` 成功
- `1001` 参数错误
- `1002` 未登录
- `1003` 权限不足
- `2001` 验证码错误/过期
- `2002` 验证码发送频繁
- `3001` 积分不足
- `3002` 订单已过期
- `4001` 资源不存在
- `4002` 资源已失效
- `5000` 系统繁忙

### 4.3 鉴权机制
- **C 端用户**：Session + Cookie（ThinkPHP `Session` 中间件，Redis 驱动）
- **后台管理员**：独立 Session 域 `admin_`，与前台隔离
- **关键操作**：CSRF Token 校验（表单 + Ajax）
- **支付回调**：免鉴权，靠签名校验

### 6.1 队列定义（`config/queue.php`）

```php

    'default' => 'redis',
    'connections' => [
        'redis' => [
            'type' => 'redis',
            'queue' => 'default',
        ],
    ],
    'channels' => [
        'crawl'    => 'crawl_queue',    // 爬虫采集
        'mail'     => 'mail_queue',     // 邮件发送
        'stat'     => 'stat_queue',     // 统计聚合
    ],
];
```

### 6.2 队列任务清单

| 队列 | 任务 | 触发方式 | 失败策略 |
|---|---|---|---|
| crawl | 采集单个网盘源 | 定时分发 | 重试 3 次，指数退避 |
| mail | 发送单封邮件 | 接口触发 | 重试 3 次 |
| stat | 广告曝光/点击聚合 | Redis 触发 | 重试 5 次 |
| stat | 用户行为日志落库 | 接口触发异步 | 重试 3 次 |

### 6.3 定时任务（crontab）

```bash
# 每分钟扫描待执行采集任务并分发
* * * * * cd /path && php think crawl:dispatch

# 每分钟关闭过期订单
* * * * * cd /path && php think order:close

# 每天 0 点聚合广告统计
0 0 * * * cd /path && php think ad:agg

# 每天 0 点归档热搜词
0 0 * * * cd /path && php think hot:archive

# 每小时清理过期验证码记录
0 * * * * cd /path && php think verify:clean
```

### 6.4 队列消费启动（supervisor 守护）

## 八、安全设计

### 8.1 认证与会话
- Session ID 使用 PHP 原生安全生成，绑定 IP+UA 指纹
- 登录后 7 天免密（勾选记住我），否则浏览器关闭即失效
- 后台 Session 与前台完全隔离（不同 cookie 名 + 不同 Redis 前缀）

### 8.2 密码与敏感数据
- 用户密码：`password_hash()` BCrypt（cost=12）
- 管理员密码：同上
- SMTP 授权码：AES-256-GCM 加密存储，密钥来自 `.env`
- 支付密钥：不存数据库，仅存 `.env`
- 数据库连接密码：仅 `.env`

### 8.3 接口安全
- 所有写操作强制 CSRF Token
- Ajax 接口校验 `X-Requested-With`
- 支付回调白名单 IP（如彩虹易支付服务器 IP 段）+ 签名双重
- 文件上传：MIME + 后缀双校验，存独立子域，禁止执行权限

### 8.4 防注入与 XSS
- 全面使用 ThinkPHP ORM 参数绑定，禁止原生 SQL 拼接
- 模板输出默认 HTML 转义
- 富文本字段（资源简介）入库前走 HTMLPurifier 清洗

### 8.5 防刷与风控
- 限流（见 5.3）
- IP 黑名单（后台可配）
- 注册邮箱白名单/黑名单（可选）
- 同一设备指纹短时间多次注册告警
- 异常登录告警（异地/新设备）

### 8.6 日志与审计
- 全局异常日志（`runtime/log/`）
- 慢请求日志（>1s）
- 管理员操作日志（变更前后 JSON）
- 支付日志（原始回调数据保留 1 年）
- 邮件发送日志

## 九、性能与扩展

### 9.1 数据库优化
- 主键 BIGINT 自增，避免 UUID 索引膨胀
- 软删除字段 `delete_time` 加索引，查询带 `WHERE delete_time IS NULL`
- `resources` 表按年分表预留（`resources_2026`、`resources_2027`）
- `credit_logs`、`crawl_logs`、`payment_logs` 等日志表按月分表
- FULLTEXT 索引使用 `WITH PARSER ngram`，ngram_token_size=2

### 9.2 查询优化
- 列表查询必走索引，禁止 `SELECT *`
- 大表 COUNT 使用 Redis 计数器或近似值
- 分页深度大时改用游标分页（`WHERE id > ? LIMIT N`）

### 9.3 ES 接入预留
- `SearchDriverInterface` 抽象层，切换驱动仅改配置
- 资源入库时同步推送到 ES（通过队列异步）
- 提供降级开关：ES 故障自动回退 MySQL

### 9.4 静态资源优化
- 公共静态资源走 CDN
- 图片资源懒加载
- 启用 HTTP/2、gzip、brotli
- 配置长缓存（带 hash 文件名）

## 十二、架构决策记录（ADR）

### ADR-001: 选择模板渲染而非前后端分离
- **背景**：用户明确要求"原生 PHP"
- **决策**：使用 ThinkPHP8 View + 原生 PHP 标签模板
- **权衡**：丧失 SPA 交互体验，但降低复杂度、利于 SEO、契合技术栈定位
- **后续**：如需复杂交互（如无限滚动搜索），局部引入 Alpine.js

### ADR-002: 搜索起步用 MySQL FULLTEXT 而非 ES
- **背景**：初期资源量预估 < 100 万，ES 运维成本高
- **决策**：MySQL 8.0 FULLTEXT + ngram 解析器
- **权衡**：百万级以下性能可接受；超出后需迁移
- **预留**：`SearchDriverInterface` 抽象层，配置切换即可上 ES

### ADR-003: 验证码仅 Redis + 数据库双写
- **背景**：验证码高频读 + 短时效，纯 DB 压力大
- **决策**：Redis 主存（校验）+ DB 审计（溯源）
- **权衡**：双写有少量不一致风险，但验证码本身时效短可接受

### ADR-004: 爬虫使用队列异步而非同步采集
- **背景**：网盘采集耗时长（几秒到几十秒）
- **决策**：定时任务分发 → 队列异步消费
- **权衡**：增加运维复杂度（需 supervisor），但避免请求阻塞

### ADR-005: 用户密码可选，主推邮箱验证码登录
- **背景**：用户要求"邮件验证码注册登录"
- **决策**：默认无密码，验证码登录；可选设置密码
- **权衡**：减少密码泄露风险，但依赖邮箱可达性
