## 一、总结

新增 `install.sh` 脚本，实现真·一条命令一键部署：自动检查并安装 Docker / git、自动克隆仓库（如不在仓库内）、自动生成随机密码、自动启动服务、轮询健康检查、最终输出访问地址与凭据。

### 调用方式（任选其一）

```bash
# 方式 A：远程一条命令（无需先 clone）
curl -fsSL https://raw.githubusercontent.com/laobi465/xiaosou/main/install.sh | bash

# 方式 B：自定义端口
curl -fsSL https://raw.githubusercontent.com/laobi465/xiaosou/main/install.sh | bash -s -- -p 9000

# 方式 C：本地仓库内
./install.sh
./install.sh -p 9000
```

### 与现有 `docker-deploy.sh` 的分工

| 脚本 | 定位 | 命令示例 |
|---|---|---|
| `install.sh`（新增） | **首次安装**：自动检测环境、生成密码、启动、等待就绪、输出凭据 | `curl ... \| bash` |

`docker-deploy.sh` 保留不动，避免破坏既有运维习惯。

## 二、当前状态分析

### 2.1 现有 `docker-deploy.sh` 的不足

读取 [docker-deploy.sh](file:///workspace/docker-deploy.sh) 第 40-55 行 `init_env()`：

```bash
init_env() {
    if [ ! -f "${ENV_FILE}" ]; then
        cp .env.docker.example "${ENV_FILE}"
        echo "[部署] 请编辑 ${ENV_FILE} 修改密码、邮件、支付等配置后重新运行本脚本"
        exit 0   # ← 首次运行直接退出，要求用户 vi 后再跑
    fi
}
```

问题：
1. 首次运行 `cp` 样例后**直接退出**，要求用户手动 `vi` 编辑 → 不是一条命令
2. 不会自动检测/安装 Docker
3. 不会自动生成随机密码（用户必须手填）
4. 等待就绪用 `sleep 30`（第 73 行），不轮询 healthcheck
5. 不会克隆仓库（远程 `curl | bash` 无法用）
6. 输出信息不含本次生成的随机密码

### 2.2 现有可复用资产

- [docker-compose.yml](file:///workspace/docker-compose.yml) 已含 4 服务 + healthcheck（app/mysql/redis 均配置 `healthcheck`）
- [docker/entrypoint.sh](file:///workspace/docker/entrypoint.sh) 已实现：等待 MySQL/Redis → 生成 .env → 创建管理员
- [.env.docker.example](file:///workspace/.env.docker.example) 含全部环境变量样例
- [Dockerfile](file:///workspace/Dockerfile) 已就绪

`install.sh` 只需在宿主机层面做：检测环境 → 生成 `.env.docker`（含随机密码）→ `docker compose up -d --build` → 轮询健康检查 → 输出结果。容器内的初始化（建表/建管理员）由现有 entrypoint 完成。

### 2.3 随机密码生成策略

| 变量 | 生成方式 | 长度 |
|---|---|---|
| `DB_PASSWORD` | `openssl rand -hex 12` | 24 字符 |
| `DB_ROOT_PASSWORD` | `openssl rand -hex 16` | 32 字符 |
| `REDIS_PASSWORD` | `openssl rand -hex 12` | 24 字符 |
| `ADMIN_PASSWORD` | `openssl rand -base64 9 \| tr -d '/+=' \| cut -c1-12` | 12 字符（避免特殊字符） |
| `APP_KEY` | `openssl rand -hex 16` | 32 字符 |
| `AES_KEY` | `openssl rand -hex 16` | 32 字符 |

`openssl` 不可用时回退到 `head -c 16 /dev/urandom \| xxd -p` 或 `cat /proc/sys/kernel/random/uuid \| tr -d '-'`。

## 三、变更方案

### 变更 1：新增 `install.sh`（核心）

**文件**：`/workspace/install.sh`（新建）

**功能清单**：
1. 解析参数 `-p PORT`（默认 8080）、`-h` 帮助
2. 检测 `docker` 命令，未安装则自动调用 `get.docker.com` 安装并启动守护进程
3. 检测 `docker compose`（v2）或 `docker-compose`（v1），均无则报错
4. 检测 `git`，未安装则自动 `apt/yum install git`
5. 检测当前目录是否含 `docker-compose.yml`：
   - 否 → 自动 `git clone https://github.com/laobi465/xiaosou.git` 到临时目录并 `cd`
   - 是 → 直接使用当前目录
6. 生成 `.env.docker`（如已存在则跳过生成步骤，保留用户既有配置）：
   - 端口用参数值
   - 所有密码用 `openssl rand` 生成
   - 邮件 / 支付字段留空（用户后续可编辑）
7. `docker compose --env-file .env.docker up -d --build`
8. 轮询健康检查：
   - 先等 MySQL 健康（`docker inspect` 读 `State.Health.Status`）
   - 再等 app 容器健康（curl `http://127.0.0.1:${PORT}/healthz`）
   - 最长 240 秒，超时则输出诊断日志并退出
9. 输出最终信息：
   - 前台 / 后台访问 URL
   - 管理员账号 + 本次生成的密码（高亮提示保存）
   - 数据库 / Redis 密码（提示保存）
   - 后续运维命令提示（`./docker-deploy.sh logs` 等）
   - 邮件 / 支付未配置的提醒

**关键实现细节**：
- 使用 `set -euo pipefail` 严格模式
- 所有日志带 `[install]` 前缀，彩色输出（绿/黄/红）
- `curl | bash` 模式下脚本通过 `bash -s --` 接收参数
- 远程模式下 `git clone` 到 `${HOME}/pansou-deploy` 固定路径，方便用户后续找
- 失败时输出 `docker logs` 摘要辅助排查

## 四、假设与决策

| 项 | 决策 | 理由 |
|---|---|---|
| 是否替换 `docker-deploy.sh` | 否，新增 `install.sh` | `docker-deploy.sh` 已有 down/logs/restart 等运维子命令，保留更稳；`install.sh` 专注首次安装 |
| 邮件 / 支付是否交互询问 | 否，留空 + 提示 | "真一条命令"原则：零交互；用户可后续 `vi .env.docker` + `./docker-deploy.sh restart` |
| 端口是否交互询问 | 否，默认 8080，支持 `-p` 参数 | 零交互；冲突时脚本检测并报错引导用户加 `-p` |
| 远程模式 clone 目标路径 | `${HOME}/pansou-deploy` | 固定路径，用户能找到；已存在则 `git pull` 更新 |
| 密码生成工具 | `openssl rand` 优先，回退 `/dev/urandom` | 兼容 Alpine / CentOS / Ubuntu |
| 是否自动安装 Docker | 是，调用 `get.docker.com` | "自动检查安装部署"明确要求；脚本会先询问 `-y` 确认（非交互模式跳过） |
| healthcheck 超时 | 240 秒 | MySQL 首次初始化 + 镜像构建可能较慢 |
