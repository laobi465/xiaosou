## 三、实施方案

### 3.1 SmtpMailer 优先读 system_configs

**文件**：[extend/Pansou/Mail/SmtpMailer.php](file:///workspace/extend/Pansou/Mail/SmtpMailer.php)

**变更**：`configure()` 方法读取优先级改为 system_configs → .env → 默认值。

```php
protected function configure(): void
{
    // 优先读 system_configs(后台 /admin/config 可在线修改),降级 .env,再降级默认值
    $cfg = $this->loadConfig();
    
    $host       = (string) ($cfg['smtp_host']       ?? env('MAIL.SMTP_HOST')       ?? 'smtp.qq.com');
    $port       = (int)    ($cfg['smtp_port']       ?? env('MAIL.SMTP_PORT')       ?? 465);
    $user       = (string) ($cfg['smtp_user']       ?? env('MAIL.SMTP_USER')       ?? '');
    $pass       = (string) ($cfg['smtp_pass']       ?? env('MAIL.SMTP_PASS')       ?? '');
    // SMTP_FROM 无 system_configs 白名单,用 user 兜底(.env 优先),保持原逻辑
    $from       = (string) (env('MAIL.SMTP_FROM') ?? $user);
    $fromName   = (string) ($cfg['smtp_from_name']  ?? env('MAIL.SMTP_FROM_NAME')  ?? '网盘搜索');
    $encryption = (string) ($cfg['smtp_encryption'] ?? env('MAIL.SMTP_ENCRYPTION') ?? 'ssl');
    
    // ... 原有 PHPMailer 配置逻辑不变
}

/**
 * 从 system_configs 加载 smtp 分组配置
 * ConfigService 经 LoadConfig 中间件已预加载到容器,失败降级返回空数组
 */
protected function loadConfig(): array
{
    try {
        if (class_exists(\app\common\service\ConfigService::class)) {
            return app(\app\common\service\ConfigService::class)->getGroup('smtp');
        }
    } catch (\Throwable $e) {
        // ignore
    }
    return [];
}
```

**理由**：
- system_configs 优先 → 后台 /admin/config 改了立即生效
- .env 降级 → 安装向导写入 .env 的初始配置仍可用
- 默认值兜底 → 无任何配置时回到原行为
- class_exists 防护 → extend 库被外部使用时不依赖 app 目录

### 3.2 CaihongPay 优先读 system_configs

**文件**：[extend/Pansou/Pay/CaihongPay.php](file:///workspace/extend/Pansou/Pay/CaihongPay.php)

**变更**：`readConfig()` 方法在 config()/env() 之前增加 system_configs 读取。

```php
protected function readConfig(string $name, string $envKey, string $configKey): string
{
    // 1. system_configs 优先(后台 /admin/config 可在线修改)
    // pay.caihong_pid → key 在 system_configs 表中为 caihong_pid(无 caihong. 前缀)
    $sysKey = str_replace('pay.caihong.', '', $configKey);
    try {
        if (class_exists(\app\common\service\ConfigService::class)) {
            $val = app(\app\common\service\ConfigService::class)->get($sysKey);
            if ($val !== null && $val !== '') {
                return (string) $val;
            }
        }
    } catch (\Throwable $e) {
        // ignore
    }
    
    // 2. config/pay.php 优先(原逻辑)
    if (function_exists('config')) {
        $val = config($configKey);
        if ($val !== null && $val !== '') {
            return (string) $val;
        }
    }
    // 3. env 兜底(原逻辑)
    if (function_exists('env')) {
        $val = env($envKey);
        if ($val !== null && $val !== '') {
            return (string) $val;
        }
    }
    return '';
}
```

**理由**：
- 保持原有 config()/env() 优先级不变，只在最前插入 system_configs 读取
- `$sysKey` 转换：pay.caihong_pid → caihong_pid（与 ConfigService 白名单一致）
- notify_url/return_url 同理：pay.caihong.notify_url → notify_url

### 3.3 ConfigService 缓存失效说明（无需改动）

[ConfigService::set()](file:///workspace/app/common/service/ConfigService.php#L215) 已调用 `flushGroup($group)` 清除 Redis 缓存与内存容器。SmtpMailer/CaihongPay 下次实例化时会重新读 ConfigService → 内存容器（已刷新）或 DB。**无需额外改动**。

## 四、假设与决策

| 项 | 决策 | 理由 |
|---|---|---|
| 配置读取优先级 | system_configs > .env > 默认值 | 后台在线修改即时生效，.env 作为兜底 |
| SMTP_FROM 是否加白名单 | 不加 | 发件人通常等于 SMTP 用户名，保持原 user 兜底逻辑；如需独立配置仍走 .env |
| 是否改动 ConfigService | 不改动 | 已有 get/getGroup/set/flushGroup 完整闭环 |
| 是否改动 LoadConfig 中间件 | 不改动 | 已预加载 system_configs 到容器 |
| 是否改动 PayService 构造注入 | 不改动 | CaihongPay 内部 readConfig 已统一入口 |
| Docker 路径是否读 system_configs | 不读（无 DB 持久化场景） | Docker 用 .env.docker 注入环境变量，system_configs 表数据在容器内 |
| 后台配置页是否加 UI 提示 | 加（轻量） | 提升用户感知，确认修改即生效 |
